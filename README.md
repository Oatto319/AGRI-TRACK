# ระบบรายงานปุ๋ยอินทรีย์และวัสดุอินทรีย์รายเดือน

โปรเจค Next.js 16 สำหรับให้อำเภอบันทึกรายงานรายเดือน และให้จังหวัดดูสรุป/ดาวน์โหลด Excel

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด `http://localhost:3000`

## เส้นทางหลัก

- `/` เข้าสู่ระบบ (ตรวจบัญชีจริงจากฐานข้อมูล)
- `/public` **ภาพรวมสำหรับประชาชน** ไม่ต้องเข้าสู่ระบบ: ยอดรวมทั้งจังหวัด แผนที่รายอำเภอ แนวโน้มเทียบเป้า (ไม่มีชื่อผู้รายงานหรือสถานะส่งช้า) · ปิดได้ด้วย `PUBLIC_DASHBOARD=off`
- `/change-password` เปลี่ยนรหัสผ่านของตัวเอง (บัญชีใหม่/ถูกรีเซ็ตต้องเปลี่ยนก่อนใช้งาน)
- `/province/users` **จัดการผู้ใช้**: เพิ่มบัญชี ปิด/เปิดใช้งาน รีเซ็ตรหัสผ่าน (ระบบสร้างรหัสให้และแสดงครั้งเดียว)
- `/district` Dashboard และประวัติรายงานของอำเภอ
- `/district/report` กรอก บันทึกร่าง หรือส่งรายงานรายเดือน
- `/province` Dashboard สรุปผลระดับจังหวัด
- `/province/table` ตารางรายอำเภอและดาวน์โหลด Excel
- `/province/settings` หน้าตั้งค่าเดียวของจังหวัด มี 2 ส่วน: **การรายงาน** (จำนวนครั้งต่อเดือน วันกำหนดส่ง พื้นที่ปลูกพืช จำนวนเกษตรตำบลรายอำเภอและเป้าหมายการผลิตปุ๋ยอินทรีย์/วัสดุอินทรีย์) และ **หัวข้อและรายการ** (ปีงบประมาณ ช่องปุ๋ย ช่องหยุดเผา ตัวคูณไถกลบ ชื่อหัวตาราง) · เปิดส่วนหลังตรง ๆ ได้ที่ `/province/settings#config` · `/province/config` เดิมจะพาไปที่นี่อัตโนมัติ
- ปุ่ม **ประวัติการส่งรายเดือน** ในหน้า `/province/table` เปิดหน้าต่างดูว่าแต่ละอำเภอส่งตรงเวลา ส่งช้า ยังไม่ส่ง หรือยังไม่ถึงกำหนด แยกตามเดือน รอบ และหัวข้อ (โค้ด `components/SubmissionHistory.tsx`, ตรรกะ `submissionByMonth` ใน `lib/summary.ts`)
- (รายละเอียดเดิมของหน้าตั้งค่า) ตั้งค่าจำนวนครั้งที่ต้องรายงานต่อเดือนและวันกำหนดส่งของแต่ละรอบ
- `/api/settings` อ่าน/บันทึกการตั้งค่ารอบรายงาน
- `/api/export?from=YYYY-MM&to=YYYY-MM` ดาวน์โหลดไฟล์ Excel ตามช่วงเดือน
- `/api/export-pdf?fy=2569` ดาวน์โหลดรายงาน PDF 1 หน้า "รายงานสรุป ประจำปีงบประมาณ" เปรียบเทียบย้อนหลัง 3 ปีงบประมาณ (2567–2569) พร้อมการ์ดการประชาสัมพันธ์เรื่องการหยุดเผา (จำนวนครั้งของปีนั้น เทียบ 3 ปี และจำนวนอำเภอที่จัดกิจกรรม) · ปุ่ม "ดาวน์โหลด PDF" อยู่ที่หน้า Dashboard และหน้าตารางจังหวัด · โค้ดอยู่ที่ `lib/pdf.ts` ใช้ฟอนต์ Sarabun (`assets/fonts/`)

## ข้อมูลและการตั้งค่า

- รายชื่ออำเภอและช่องข้อมูลอยู่ใน `lib/data/` (แยกเป็น `constants` `types` `dates` `fiscal` `area` `config` `validate` · import จาก `@/lib/data` ได้เหมือนเดิม)
- ข้อมูลทั้งหมดเก็บใน **MongoDB**: คอลเลกชัน `reports`, `area_reports`, `burn_reports`, `settings`, `app_users`, `sessions`, `login_attempts` (สร้างเองอัตโนมัติ พร้อม index; `sessions` และ `login_attempts` มี TTL ลบเองเมื่อหมดอายุ) · โค้ดอ่าน/เขียนอยู่ที่ `lib/store.ts` และ `lib/users.ts` · การเชื่อมต่อที่ `lib/mongo.ts`
- เซิร์ฟเวอร์เชื่อมผ่าน `MONGODB_URI` (เก็บใน `.env.local` เท่านั้น ห้ามขึ้น git) และไม่เคยส่งค่านี้ไปฝั่งเบราว์เซอร์

### ตั้งค่า MongoDB (ทำครั้งเดียว)

1. เตรียม MongoDB อย่างใดอย่างหนึ่ง: ติดตั้งบนเครื่อง (`mongodb://127.0.0.1:27017`) หรือสร้างคลัสเตอร์ฟรีบน MongoDB Atlas (ต้องเพิ่ม IP ใน Network Access และสร้าง Database User)
2. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ `MONGODB_URI` (และ `MONGODB_DB` ถ้าต้องการ)
3. `npm install`
4. ถ้ามีข้อมูลเดิมในโฟลเดอร์ `data/` ให้ย้ายขึ้น MongoDB ด้วย `npm run migrate:json` (ย้ายรายงาน การตั้งค่า และบัญชีผู้ใช้ รันซ้ำได้)
5. ถ้ายังไม่มีบัญชีผู้ใช้ ให้สร้างด้วย `npm run seed:users` (รหัสผ่านตัวจริงอยู่ที่ `data/initial-credentials.csv` แจกแล้วลบทิ้ง)
- บัญชีที่สร้างด้วย `seed:users` หรือหน้า `/province/users` จะถูกบังคับให้เปลี่ยนรหัสผ่านตอนเข้าครั้งแรก · บัญชีเดิมที่สร้างก่อนอัปเดตนี้ยังใช้รหัสเดิมได้ตามปกติ (ถ้าต้องการให้เปลี่ยน ให้กด "รีเซ็ตรหัสผ่าน" ในหน้าจัดการผู้ใช้)

เมื่อใช้ MongoDB Atlas (`mongodb+srv://`) แอปจะค้นหา SRV/TXT records ด้วย DNS resolver ที่กำหนดใน `MONGODB_DNS_SERVERS` (ค่าเริ่มต้น `8.8.8.8`) แล้วเชื่อมต่อผ่าน seed hosts โดยตรง เพื่อหลีกเลี่ยงปัญหา `querySrv ECONNREFUSED` ใน MongoDB driver หากเครือข่ายบล็อก DNS นี้ ให้กำหนด DNS ที่เครือข่ายอนุญาตใน `.env.local` แล้วรีสตาร์ตเซิร์ฟเวอร์; ตรวจด้วยว่า Atlas อนุญาต IP ปัจจุบันใน Network Access

## รอบรายงานและการส่งช้า

- เป้าหมายการผลิตปุ๋ยอินทรีย์/วัสดุอินทรีย์ของอำเภอ = จำนวนเกษตรตำบล × ตัวคูณต่อราย (ค่าเริ่มต้นในฟอร์มตั้งค่า 130 ตัน) ตั้งรายปีงบประมาณที่ `/province/settings` (เก็บใน `settings` คีย์ `tambonSets`) · ปีที่ยังไม่ตั้งใช้จำนวนเริ่มต้นของอำเภอและตัวคูณจากส่วน "หัวข้อและรายการ"
- จังหวัดตั้งค่าที่ `/province/settings`: จำนวนครั้งต่อเดือน (1–4) และวันที่กำหนดส่งของแต่ละรอบ (31 = สิ้นเดือน) เก็บในคอลเลกชัน `settings`
- อำเภอกรอกแยกตามรอบ (เดือน + รอบที่) แต่ละรอบกรอกเฉพาะปริมาณของรอบนั้น ระบบรวมทุกรอบเป็นยอดของเดือน
- เมื่อส่งรายงาน ระบบบันทึกวัน-เวลาที่ส่งและเทียบกับวันกำหนด (เวลาประเทศไทย) หากเกินกำหนดจะแสดง "ส่งช้า" พร้อมวันที่ส่ง ในหน้ากรอก Dashboard อำเภอ ตารางจังหวัด และชีต "บันทึกการส่ง" ในไฟล์ Excel
- สถานะส่งช้านับจากการส่งครั้งแรก การแก้ไขแล้วส่งซ้ำไม่เปลี่ยนวันที่ส่งหรือสถานะ
- รายงานเก่าที่ไม่มีข้อมูลรอบ ถือเป็นรอบที่ 1 และแสดงว่า "ไม่มีบันทึกวันที่ส่ง"
- ทุก API (`/api/reports`, `/api/area`, `/api/burn`, `/api/export*`) ตรวจ session ฝั่งเซิร์ฟเวอร์ · อำเภอกรอกรายงานได้เฉพาะอำเภอของบัญชีตัวเอง · แก้การตั้งค่าได้เฉพาะบัญชีจังหวัด · หน้าเว็บอ่านตัวตนจาก `/api/me`

## ข้อมูลพื้นที่และฟางข้าว (หน้าแยก)

- **จังหวัดกำหนด** "พื้นที่ปลูกพืชทั้งหมด" ของแต่ละอำเภอที่ `/province/settings` (เก็บในคอลเลกชัน `settings` คีย์ `areaTotals`) อำเภอไม่ต้องกรอก
- **อำเภอกรอกที่** `/district/area` เฉพาะ "พื้นที่ไถกลบฟางข้าวในเดือนนี้ (ไร่)" และรายงานได้เฉพาะเดือน **พฤศจิกายน–มิถุนายน** เท่านั้น (API ปฏิเสธเดือนอื่น) ใช้รอบ กำหนดส่ง และการแสดง "ส่งช้า" ชุดเดียวกับรายงานปุ๋ยอินทรีย์
- **ระบบคำนวณให้อัตโนมัติ**
  - เป้าหมายร้อยละ 35 = พื้นที่ปลูกพืชทั้งหมด × 35 ÷ 100
  - พื้นที่สะสมทั้งหมด = ผลรวมไร่ที่อำเภอรายงานรายเดือน (ทุกรอบ) ตั้งแต่ พ.ย. จนถึงเดือนที่เลือก ภายในฤดูกาลเดียวกัน (พ.ย. ปีหนึ่ง – มิ.ย. ปีถัดไป) เริ่มนับใหม่ทุกฤดูกาล
  - คิดเป็นร้อยละ = พื้นที่สะสม ÷ พื้นที่ปลูกพืชทั้งหมด × 100
  - ปริมาณฟางข้าว (ตัน) = (ไร่สะสม × 500 กก.) ÷ 1,000
  - คิดเป็นมูลค่า (บาท) = ไร่สะสม × 725 (ไถกลบฟางข้าว 1 ไร่ = 0.5 ตัน มีธาตุอาหารหลัก 23 กก. = 725 บาท)
  - ฟางก้อน (ก้อน) = ไร่สะสม × 25 (1 ไร่ = 25 ก้อน)
  - ราคาฟางก้อน (บาท) = จำนวนฟางก้อน × 35 (1 ก้อน = 35 บาท)
- Dashboard/ตารางจังหวัดและอำเภอใช้ฤดูกาลที่เดือน "ถึงเดือน" อยู่ (ถ้าเป็น ก.ค.–ต.ค. จะใช้ฤดูกาลที่เพิ่งจบ) ค่าคงที่ 35% / 500 กก. / 725 บาท / 25 ก้อนต่อไร่ / 35 บาทต่อก้อน อยู่ใน `lib/data.ts` สูตรสรุปอยู่ใน `lib/summary.ts` (`aggregateArea`)
- ข้อมูลเก็บในคอลเลกชัน `area_reports` · API: `/api/area` · รายงานพื้นที่รูปแบบเก่า (ที่กรอกพื้นที่สะสม/ฟางข้าวเอง) จะอ่านได้แต่นับเป็น 0 ต้องกรอกใหม่เป็นไร่รายเดือน · ไฟล์ Excel มีชีต "พื้นที่และฟางข้าว"

## สร้างการเรียนรู้/ประชาสัมพันธ์เรื่องการหยุดเผา (หน้าแยก)

- **อำเภอกรอกที่** `/district/burn` รายงานได้ทุกเดือน ใช้รอบ กำหนดส่ง และการแสดง "ส่งช้า" แบบเดียวกับหัวข้ออื่น
- ช่องที่กรอก (จำนวนเต็ม) กำหนดไว้ที่ `BURN_FIELDS` ใน `lib/data.ts`: จำนวนกิจกรรม (ครั้ง) · หมู่บ้าน/ชุมชนที่ดำเนินการ · ผู้เข้าร่วม (ราย) · สื่อประชาสัมพันธ์ที่เผยแพร่ (ชิ้น) — เพิ่ม/แก้ช่องได้ที่นั่นที่เดียว
- รอบและวันกำหนดส่งใช้ค่าเริ่มต้น (`dueDays`) ของจังหวัด ไม่มีรายการตั้งค่าแยกในหน้าตั้งค่า
- จังหวัดดูสรุปรายอำเภอที่ `/province/table` แท็บ "การเรียนรู้/ประชาสัมพันธ์หยุดเผา" และไฟล์ Excel มีชีต "การหยุดเผา"
- ข้อมูลเก็บในคอลเลกชัน `burn_reports` · API: `/api/burn` · รองรับการย้ายจาก `data/burn-reports.json` ด้วย `npm run migrate:json`

## ตั้งค่าหัวข้อและรายการโดยไม่ต้องแก้โค้ด (เฉพาะจังหวัด)

- ส่วน "หัวข้อและรายการ" ในหน้า `/province/settings` ให้เจ้าหน้าที่จังหวัด:
  - เพิ่ม/ลบ **ปีงบประมาณ** (แสดงในตัวเลือกปีงบประมาณทุกหน้าและหน้าตั้งค่าการรายงาน)
  - เพิ่ม/ลบ/เปลี่ยนชื่อ/ย้ายกลุ่ม/เรียงลำดับ **ช่องปุ๋ย** และ **ช่องรายงานการหยุดเผา** (ชื่อ กลุ่ม หน่วย)
  - ปรับตัวคูณ **ไถกลบฟางข้าว/ฟางก้อน** (ร้อยละเป้าหมาย, กก./ไร่, บาท/ไร่, ก้อน/ไร่, บาท/ก้อน) และเป้าหมายปุ๋ยต่อเกษตรตำบล
  - แก้ **ชื่อหัวข้อที่ต้องรายงาน** และ **หัวตาราง/ข้อความ** ทุกรายการใน `LABEL_DEFS` (`lib/data.ts`) · เว้นว่าง = ใช้ข้อความเดิม
- ปีงบประมาณแต่ละปีมีช่วงเดือนรวม (เดือนเริ่ม–สิ้นสุด) และกำหนดช่วงเดือน **แยกตามหัวข้อ** ได้ (ปุ๋ยอินทรีย์ / ไถกลบฟางข้าว / หยุดเผา) เช่น ไถกลบ พ.ย.–มิ.ย. แต่ปุ๋ยรายงานถึง พ.ค. · หัวข้อที่ไม่กำหนดใช้ช่วงรวมของปี · เก็บใน `config.fiscalYears[].topics`
- ค่าทั้งหมดเก็บใน MongoDB: คอลเลกชัน `settings` เอกสาร `main` ฟิลด์ `data.config` (ยังไม่เคยตั้งค่า = ใช้ค่าเริ่มต้นเดิมของระบบ) ใช้กับแบบฟอร์มอำเภอ Dashboard ตาราง Excel และ PDF
- การลบช่องคือการซ่อนจากหน้าจอ/ไฟล์ ข้อมูลที่อำเภอเคยกรอกยังอยู่ในฐานข้อมูลและไม่ถูกลบ
- **สิทธิ์:** ตอนนี้ล็อกอินออก cookie `agri_session` ที่เซิร์ฟเวอร์เซ็น (HMAC) และ `PUT /api/settings` อนุญาตเฉพาะบัญชี role `province` (บัญชีอำเภอได้ 403)
  ต้องตั้ง `AUTH_SECRET` ใน `.env.local` (ดู `.env.example`) และต้องล็อกอินใหม่หลังอัปเดต
  API ทุกตัว (รวม `/api/reports`, `/api/area`, `/api/burn`, `/api/export`, `/api/export-pdf`) ตรวจ session ฝั่งเซิร์ฟเวอร์ · บัญชีอำเภออ่าน/เขียนได้เฉพาะอำเภอของตัวเอง (ดูหัวข้อ "ความปลอดภัย")

- **ปีงบประมาณ** นับช่วงรายงาน พ.ย. – มิ.ย. (ปี 2570 = พ.ย. 2569 – มิ.ย. 2570) กำหนดที่ `FY_START_MONTH` / `FY_END_MONTH` ใน `lib/data.ts` · เดือน ก.ค. – ต.ค. นับเป็นของปีงบประมาณถัดไป · ข้อมูลเดือนนอกช่วง พ.ย.–มิ.ย. จะไม่รวมในสรุปรายปีงบประมาณ

- **ธีมสี**: โทนเกษตรจังหวัด เขียวนาข้าว (#1b4a2e/#2f7d4f) · ทองรวงข้าว (#c19a36) · น้ำตาลดิน (#8a5a2b) พื้นหลังครีมอมเขียว แก้ตัวแปรสีที่ต้นไฟล์ `app/globals.css` และ `app/ux.css`

- **ตั้งค่าแยกรายปีงบประมาณ**: หน้า `/province/settings` ส่วน "หัวข้อและรายการ" เลือกปีงบประมาณที่จะแก้ไขได้ (ช่องปุ๋ย ช่องหยุดเผา ตัวคูณ ชื่อหัวข้อ/หัวตาราง) เก็บที่ `data.config.byYear["2570"]` · ปีที่ไม่ได้ตั้งเองใช้ "ค่าตั้งต้น" (`data.config` ระดับบนสุด) · มีปุ่มคัดลอกจากปีอื่น/ใช้ค่าตั้งต้นแทน · ตัวเลขทุกหน้า/Excel/PDF ใช้ค่าของปีงบประมาณที่ดูอยู่ (ช่วงที่ข้ามหลายปีใช้ค่าของปีสุดท้าย)

- **ช่วงเดือนของปีงบประมาณ**: แต่ละปีที่เพิ่มในหน้า `/province/settings` ส่วน "หัวข้อและรายการ" กำหนด เดือนเริ่ม–เดือนสิ้นสุด ได้เอง (เช่น พ.ย.–มิ.ย.) และกดแก้ไข/ลบภายหลังได้ · เก็บที่ `data.config.fiscalYears[]` = `{fy, startMonth, endMonth}` (ข้อมูลเก่าที่เป็นเลขปีล้วนแปลงเป็น พ.ย.–มิ.ย. อัตโนมัติ) · ปีที่ไม่ได้เพิ่มเองใช้ พ.ย.–มิ.ย.

- ฤดูกาลไถกลบ/ช่วงเดือนที่รายงานพื้นที่ได้ ตามช่วงเดือนของปีงบประมาณที่ตั้งไว้ (ค่าเริ่มต้น พ.ย.–มิ.ย.) · หน้ารายงานปุ๋ยและหยุดเผาของอำเภอเตือนเมื่อเลือกเดือนนอกช่วงปีงบประมาณ (ข้อมูลไม่ถูกนับในสรุปรายปี)

- หน้า `/district/area`: เลือก **ปีงบประมาณ** ก่อน แล้วระบบแสดง **เดือนที่ต้องส่งทั้งหมดของปีนั้น** เป็นปุ่ม พร้อมสถานะแต่ละเดือน (ส่งครบ / ส่งบางรอบ / มีร่าง / ยังไม่ส่ง / เลยกำหนด) ตามช่วงเดือนที่จังหวัดตั้งไว้

## ความปลอดภัย

- **Session ฝั่งเซิร์ฟเวอร์**: cookie เซ็นด้วย `AUTH_SECRET` และทุก API ตรวจ `sessions` ในฐานข้อมูลด้วย (`lib/auth.ts`) · ออกจากระบบ/ปิดบัญชี/รีเซ็ตหรือเปลี่ยนรหัสผ่านแล้ว token เดิมใช้ไม่ได้ทันที · สิทธิ์ (role/อำเภอ) ใช้ค่าจากบัญชีในฐานข้อมูลเสมอ
- **`proxy.ts`** กันหน้า `/district` `/province` `/change-password` สำหรับผู้ที่ยังไม่ล็อกอิน (ตรวจลายเซ็น/วันหมดอายุ) ส่วนสิทธิ์จริงตรวจที่ API
- **จำกัดการเดารหัสผ่าน**: ผิด 5 ครั้งต่อชื่อผู้ใช้ (หรือ 30 ครั้งต่อ IP) ใน 15 นาที ถูกล็อก 15 นาที — จังหวัดรีเซ็ตรหัสผ่านเพื่อปลดล็อกได้ · IP อ่านจาก `X-Forwarded-For` จึงควรรันหลัง reverse proxy ที่เชื่อถือได้
- **แยกข้อมูลตามอำเภอ**: อำเภออ่าน/เขียนได้เฉพาะของตัวเอง (`GET /api/reports|area|burn` คืนเฉพาะอำเภอของบัญชี)
- **กันบันทึกทับกัน**: แต่ละรายงานมี `version` (optimistic locking) ถ้ามีคนแก้ตัดหน้าจะได้ HTTP 409 แทนการเขียนทับเงียบ ๆ
- กัน CSRF ด้วยการตรวจ `Origin` + `sameSite=lax` · ตั้ง security headers ใน `next.config.ts`
- ต้องมีเทสต์ guard (`tests/api/guard.test.ts`) ที่ตรวจว่าทุก API เรียก `requireSession` พร้อม `await` — ลืม `await` จะทำให้ข้ามการตรวจสิทธิ์โดยที่ TypeScript ไม่เตือน

## ฟีเจอร์ตรวจค่าผิดปกติ / แผนที่ / แนวโน้ม

- **ตรวจค่าผิดปกติ** (`lib/anomaly.ts`): ตอนอำเภอกรอกปุ๋ย/ไถกลบ ระบบเทียบกับประวัติของอำเภอนั้นเอง (มัธยฐานของรายงานที่ผ่านมา) เตือนเมื่อสูงกว่าปกติ ≥3 เท่า, เป็น 0 หลังมีค่าติดกัน 3 ครั้ง, ช่องเดียวเกินครึ่งของเป้าทั้งปี หรือยอดสะสมเกินเป้า 1.5 เท่า · เป็นการเตือนให้ยืนยันก่อนส่ง ไม่ได้ห้ามส่ง · ฝั่งจังหวัดมีการ์ด "ค่าที่ควรตรวจสอบ" ที่หน้า Dashboard · ปรับเกณฑ์ที่ `RULES`
- **แผนที่อำเภอ** (`components/DistrictMap.tsx`, ข้อมูลขอบเขต `lib/geo/sisaket.ts`): SVG ไม่พึ่งบริการภายนอก ลงสีตามร้อยละเทียบเป้า · ขอบเขตมาจาก OpenGISData-Thailand (ลดจุดแล้ว) ตรวจชื่อ 22 อำเภอตรงกับ `DISTRICTS` ครบ
- **แนวโน้มเทียบเป้า** (`lib/trend.ts`, `components/TrendChart.tsx`): เส้นสะสมจริง · เส้นควรได้ตามแผน (เท่ากันทุกเดือน) · เส้นคาดการณ์จากค่าเฉลี่ย 3 เดือนล่าสุด

## เทสต์ / CI / การเฝ้าระวัง

```bash
npm test            # unit + API integration (Vitest) — ใช้ MongoDB จำลองในหน่วยความจำ ไม่ต้องมีฐานข้อมูล
npm run typecheck
npm run lint
```

- `.github/workflows/ci.yml` รัน lint → typecheck → test → build ทุก push/PR · ตั้ง branch protection ให้ job `verify` ต้องผ่านก่อน merge/deploy
- `GET /api/health` ตรวจสุขภาพ (200 = แอปและ DB พร้อม, 503 = DB ล่ม) ใช้กับ uptime monitor/load balancer
- **Sentry** (`instrumentation.ts`, `instrumentation-client.ts`, `app/global-error.tsx`, `lib/monitoring.ts`): ตั้ง `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN` เพื่อเปิด · ไม่ตั้ง = ปิด · ตัด cookie/header/body ของคำขอก่อนส่งเสมอ · ยังไม่ได้ใส่ `withSentryConfig` (อัปโหลด source map) ถ้าต้องการให้เพิ่มใน `next.config.ts` ตามคู่มือ Sentry
- `window.confirm` ทั้งหมดถูกแทนด้วยกล่องยืนยันของระบบ (`components/ConfirmDialog.tsx`, ใช้ผ่าน `useConfirm()`)

## ข้อควรระวังด้านความปลอดภัย (สรุปจากการตรวจโค้ด)
- ค่าตัวเลขที่อำเภอกรอกรับเฉพาะเลขฐานสิบ ไม่เกิน 1,000,000,000 ต่อช่อง (`parseAmount` ใน `lib/data/validate.ts`) · ชื่อ/ตำแหน่งยาวไม่เกิน 120 ตัว เบอร์โทรไม่เกิน 20 ตัว
- ข้อผิดพลาดภายใน (เช่น ฐานข้อมูล) ตอบผู้ใช้เป็นข้อความทั่วไป (HTTP 500) และเก็บรายละเอียดไว้ใน log เท่านั้น · มีเฉพาะ `RejectError` (กฎของระบบ) ที่ส่งข้อความถึงผู้ใช้
- `/api/password` มีการจำกัดการลองรหัสผ่านเดิมผิด (5 ครั้ง/15 นาที) · `/api/logout` ตรวจ Origin เหมือน API อื่น
- `npm run seed:users -- --force` ล้าง session เดิมทั้งหมดด้วย
- การจำกัดการล็อกอินตาม IP อ่านจาก `X-Forwarded-For` จึงต้องวางระบบไว้หลัง reverse proxy ที่เชื่อถือได้ (เช่น Vercel/nginx) ซึ่งเขียนทับ header นี้เอง
- ยังไม่มี Content-Security-Policy · ควรเพิ่มเมื่อทดสอบกับ nonce ของ Next.js แล้ว
